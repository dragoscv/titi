# ADR-0003: Wire format — protobuf control + fixed voice header

Date: 2026-09-14 · Status: Accepted

## Decision
- **Control/signalling messages**: protobuf (proto3) in `proto/titi/v1/`,
  compiled with `buf` to Wire (Kotlin), swift-protobuf, protobuf-es, prost.
- **Radio envelope** (per hop, hand-packed, implemented once in Rust):

```
0     1     2     3     4..7      8..15   [16..23]
ver  type  ttl:4|hop_start:4  flags  msg_id32  src8   dst8 (if flags.UNICAST)
```
- **Voice frame** (inside group AEAD):

```
0     1      2..3      4..5   6..7
type  flags  talker16  seq16  ts16 (20 ms units)   + codec payload
flags: codec(2b) frames-1(2b) marker(1b) profile(3b)
```
- Crypto layering: outer per-link Noise/ChaChaPoly AEAD (relays verify,
  dedup, TTL−1) → inner group XChaCha20-Poly1305 (relays cannot decrypt).
- BLE fragmentation: 1-byte continuation index at the link layer, MTU-3.

## Alternatives rejected
RTP/SRTP (12 B header + second crypto layer, 47 % overhead on BLE), CBOR /
MessagePack (no schema evolution tooling), FlatBuffers (larger, generators lag).

## Consequences
`buf lint` + `buf breaking` in CI. `testvectors/` generated by Rust cover
envelope, voice header, Noise transcripts, nonce derivation and route-table
transitions.
